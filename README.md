# Askesis

Сайт для тренировок и занятий спортом — личный проект для себя и друзей.

## Стек

- **client/** — React + Vite, Firebase Auth (email/пароль + Google) + прямой доступ к Firestore через Firebase SDK
- **Firestore** — база данных (упражнения, программы, тренировки, лог выполнения); вся бизнес-логика прав — в `firestore.rules`
- **worker/** — Cloudflare Worker: прокси к Groq для ИИ-тренера. Держит API-ключ у себя и проверяет Firebase ID-токен, потому что во фронтенде ключ спрятать негде (см. [worker/README.md](worker/README.md))
- **scripts/** — разовый Node-скрипт импорта библиотеки упражнений (Admin SDK, не деплоится)

Работает целиком на бесплатном **Spark**-плане Firebase — Cloud Functions не используются (они требуют платный Blaze-план, даже в рамках бесплатной квоты — см. [PLAN.md](PLAN.md)).

Подробный план и обоснование решений — в [PLAN.md](PLAN.md). Инструкция по разворачиванию реального Firebase-проекта — в [SETUP.md](SETUP.md).

## Разделы

- Главная
- Каталог программ тренировок (курирует админ) — `/programs`; на странице программы есть кнопка «Начать программу», которая создаёт личную тренировку с теми же подходами и повторами
- Библиотека упражнений с фильтрами по группе мышц, инвентарю, уровню и категории — `/exercises`
- Сборка своей тренировки из библиотеки — `/workouts`, `/workouts/new`, редактирование — `/workouts/:id/edit`
- ИИ-тренер: пять вопросов → персональная программа — `/workouts/ai` (нужен развёрнутый воркер)
- Лог выполнения, таймер времени в зале и история по тренировке — `/workouts/:id`. Каждый подход отмечается кнопкой с номером: отметка запускает отдых (длительность по типу упражнения, ±15 с запоминаются для упражнения), сигнал вибрацией и звуком по окончании и сам запускает таймер тренировки. Если подходы отмечали, в журнал идут только отмеченные. Пока идёт тренировка, экран не гаснет (Wake Lock). Перед тренировкой — чек-ин сна, энергии и забитости мышц; у каждого упражнения отмечается запас до отказа (RIR) и есть кнопка «Заменить» с аналогами по той же группе мышц; сразу после записи открывается разбор: рекорды, объём против прошлого раза, XP, новый уровень и цель на следующую тренировку по каждому упражнению
- Сканер КБЖУ по фото еды — обрезка кадра до тарелки, распознавание калорий и БЖУ через ИИ, дневная норма из профиля и история — `/nutrition` (нужен развёрнутый воркер)
- Онбординг при регистрации: цель, опыт, частота, инвентарь → первая программа — `/onboarding`. Программа собирается из библиотеки даже без воркера, ИИ только улучшает результат
- Обзор с тренером — `/dashboard`: что делать сегодня, серия, уровень и наблюдения тренера (готовность на сегодня, застой в упражнении, отстающая группа мышц, недобор до отказа, близкая цель)
- Статистика с личными целями («жим 100 кг», «15 подтягиваний») и рекордами — `/statistics`
- Личный кабинет: статистика посещений, время в зале, календарь тренировок, история веса и графики прогресса — `/profile`
- Admin-экран (только для админа) — `/admin`
- Регистрация / вход (email+пароль, Google) — `/register`, `/login`

Сайт ставится на телефон как приложение (`client/public/manifest.webmanifest`,
иконки рядом). Service worker намеренно нет: офлайн-кэш чанков спорил бы с
перезагрузкой после деплоя (см. `main.jsx`), а введённые подходы и так
переживают потерю связи в черновике localStorage — об этом говорит плашка
«Нет сети».

## Локальная разработка

```bash
cd client && npm install
npm run dev
```

`client/.env` содержит конфиг реального Firebase-проекта — локальный dev-сервер обращается напрямую к нему (Auth + Firestore), эмуляторы не обязательны.

Для полностью локальной разработки без реального проекта нужны Firebase-эмуляторы, а для них — **Java 21+**:

```bash
firebase emulators:start --project demo-askesis
```

и `VITE_USE_FIREBASE_EMULATORS=true` в `client/.env`.

## Права доступа

Cloud Functions на Spark-плане нет, клиент ходит в Firestore напрямую — значит
[firestore.rules](firestore.rules) это единственное место, где живут права.
Правила ограничивают не только доступ, но и форму записей: суточная квота
записи общая для всех, и без потолков один пользователь мог бы залить документы
произвольного размера и остановить приложение для остальных.

Каталоги (`exercises`, `programs`) читает только вошедший пользователь. Раньше
они были открыты анониму, а один проход по библиотеке — это 873 чтения при
суточной квоте порядка 50 000. Поэтому `/exercises` и `/programs` в клиенте
теперь под `ProtectedRoute`, а вход возвращает человека туда, куда он шёл.

## Проверки

Линтер и юнит-тесты — быстрые, ничего не требуют кроме `npm install`:

```bash
cd client && npm run lint && npm test
```

Правила Firestore проверяются отдельно, против эмулятора на выдуманном проекте
`demo-askesis` — боевая база не затрагивается. Нужна **Java 21+**:

```bash
cd firestore-tests && npm install && npm test
```

Юнит-тесты (Vitest) покрывают чистую логику: фильтры библиотеки, чтение лога
тренировок в обоих форматах, ИМТ, переводы и кэш каталогов. CI на каждый push и
PR гоняет линтер, юнит-тесты, сборку и тесты правил
(см. [.github/workflows/ci.yml](.github/workflows/ci.yml)) — Java на его
раннерах ставится автоматически.

## E2E-тесты

```bash
cd client && npx playwright install chromium   # один раз
cd scripts && npm install && npm run e2e
```

Одна команда поднимает эмуляторы Auth и Firestore, засевает их тестовыми
аккаунтами и каталогом ([scripts/seedEmulator.js](scripts/seedEmulator.js)),
поднимает дев-сервер в режиме `emulator` на порту 5174 и гоняет сценарии.
Нужна **Java 21+**.

Тесты покрывают весь основной путь: регистрация и вход, каталог, сборка
тренировки и лог выполнения, дашборд, статистика, питание, admin CRUD,
диалог подтверждения и мобильная навигация на 320–414 px.

Раньше сценарии ходили в боевой проект. Так делать не стоит, и дело не
только в мусорных аккаунтах: каждый прогон вычитывал каталог из 873
документов по многу раз, а суточная квота чтений на Spark-плане общая —
несколько прогонов подряд оставляли без базы всех пользователей сразу.
В эмуляторе квоты нет, прогон втрое быстрее, а пароли тестовых аккаунтов
можно держать прямо в репозитории: за пределами машины таких
пользователей не существует. Поэтому E2E теперь есть и в CI.

Отдельный порт (5174) выбран намеренно: обычный `npm run dev` на 5173
смотрит в боевой проект, и Playwright не должен подхватить его вместо
эмуляторного.

## Кэш каталогов

Библиотека упражнений — 873 документа, и нужна она шести экранам. Без кэша
каждый переход между ними стоил бы ещё 873 чтения Firestore, то есть дневная
квота Spark-плана (50k) уходила бы примерно за 60 переходов. Поэтому
`listExercises`/`listPrograms` идут через [client/src/api/cache.js](client/src/api/cache.js):
результат живёт в localStorage (сутки для упражнений, час для программ), а в
кэш кладётся урезанная проекция без инструкций — с ними запись весила бы 1.4 МБ
вместо 260 КБ. Админские правки каталогов сбрасывают кэш сразу; админке список
отдаётся мимо кэша и целиком (`listExercisesFull`), потому что форма
редактирования правит те самые инструкции.

## Тренер

Тренер на дашборде и разбор после тренировки считаются на клиенте, а не
спрашиваются у модели: [client/src/utils/coach.js](client/src/utils/coach.js)
и [sessionReview.js](client/src/utils/sessionReview.js) — чистые функции над
уже загруженной историей, без единого дополнительного запроса.

Причины две. Первая: все нужные числа уже посчитаны соседними модулями —
серия (`streak.js`), рекорды (`records.js`), прогрессия (`progression.js`),
объём по группам (`statistics.js`). Модель, которой их пересказали словами,
начинает их искажать, и совет расходится с цифрами на том же экране. Вторая:
воркер с ИИ может быть не развёрнут или упереться в квоту Groq, а «что делать
сегодня» — не та вещь, которая имеет право пропасть.

ИИ подключается последним шагом и только пересказывает: кнопка «Что это
значит» отправляет готовые формулировки на `/coach` (см.
[worker/README.md](worker/README.md)), где промпт прямо запрещает пересчитывать
и добавлять свои числа. Без `VITE_AI_WORKER_URL` кнопки просто нет, а всё
остальное работает.

Оттуда же растут связи между тремя ИИ-фичами: наблюдение тренера ведёт в чат
уже с составленным вопросом (`/workouts/chat?q=...`), разбор после тренировки —
с сегодняшними цифрами, сканер КБЖУ — с дневными итогами.

По тому же принципу устроено и всё остальное, что похоже на «умную» функцию:

- **Прогрессия** ([progression.js](client/src/utils/progression.js)) — двойная
  прогрессия по фактическим цифрам. Запас до отказа (RIR), который человек
  отмечает после упражнения, меняет вывод сильнее самих повторений: подход с
  тремя повторениями в запасе не считается рабочим, сколько бы их ни было.
- **Цели** ([goals.js](client/src/utils/goals.js)) — факт достижения не
  хранится, а выводится из журнала, как рекорды и XP. Прогресс считается от
  результата на момент постановки цели, иначе человек с жимом 90 кг при цели
  100 видел бы «90% готово» в первый же день.
- **Первая программа** ([starterPlan.js](client/src/utils/starterPlan.js)) —
  сплит из библиотеки по ответам онбординга. Новичок не должен упереться в
  «помощник не настроен» на первом же экране, поэтому ИИ здесь только
  улучшает уже готовый результат.
- **Нормы КБЖУ** ([nutrition.js](client/src/utils/nutrition.js)) — Миффлин-Сан
  Жеор от данных профиля. Без пола считается по середине между мужской и
  женской формулой и честно помечается приблизительной.
- **Замена упражнения** ([alternatives.js](client/src/utils/alternatives.js)) —
  только та же группа мышц; инвентарь, уровень и тип движения влияют на
  порядок, но не на состав.
- **Готовность** ([readiness.js](client/src/utils/readiness.js)) — сон, энергия
  и забитость в одну оценку. Прогрессия её не видит намеренно (расчёт обязан
  оставаться воспроизводимым) — вместо этого приложение предупреждает, что
  сегодня не тот день, чтобы брать прибавку.

## Импорт библиотеки упражнений

Разовый скрипт заливает [Free Exercise DB](https://github.com/yuhonas/free-exercise-db) (800+ упражнений, public domain) в Firestore:

```bash
cd scripts
npm install
GOOGLE_APPLICATION_CREDENTIALS=./serviceAccountKey.json GCLOUD_PROJECT=<project-id> npm run import:exercises
```

См. [SETUP.md](SETUP.md) — где взять `serviceAccountKey.json`.

## Деплой

```bash
cd client && npm run build && cd ..
firebase deploy --only hosting,firestore
```

ИИ-тренер деплоится отдельно, в Cloudflare:

```bash
cd worker && npm install && npx wrangler secret put GROQ_API_KEY && npm run deploy
```

Адрес воркера из вывода команды пропишите в `client/.env` как `VITE_AI_WORKER_URL`. Пока переменная не задана, страница `/workouts/ai` честно сообщает, что помощник не настроен, — остальное приложение работает как обычно.

Пошагово — создание Firebase-проекта, включение провайдеров Auth, назначение первого админа — в [SETUP.md](SETUP.md).
