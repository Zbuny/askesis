# Askesis — план проекта

## Назначение

Личный некоммерческий проект — сайт для тренировок для себя и знакомых. Не публичный продукт: без платежей, без строгих требований к комплаенсу/масштабированию.

## Архитектура

Полностью на **Firebase**, на бесплатном **Spark**-плане — без своего сервера и без Cloud Functions:

- **Firebase Hosting** — раздача React-фронтенда (клиент из `client/` остаётся React + Vite)
- **Firestore** — база данных, клиент обращается к ней **напрямую** через Firebase SDK
- **Firestore Security Rules** — вся бизнес-логика прав (кто админ, кто владелец тренировки) живёт в `firestore.rules`, а не в серверном коде
- **Firebase Authentication** — email/пароль + Google Sign-In

Изначально планировался бэкенд на Cloud Functions (см. историю решений ниже), но Cloud Functions в принципе не деплоятся без платного плана Blaze (Google требует привязанный биллинг-аккаунт для Cloud Build API даже в рамках бесплatной квоты). Раз проект остаётся на Spark — от Cloud Functions отказались в пользу прямого доступа к Firestore.

Текущий кастомный JWT + bcrypt + in-memory хранилище в `server/` выпилено целиком — Firebase Auth закрывает эту задачу надёжнее и без лишнего кода.

## Модель данных (Firestore)

Три сущности:

1. **Упражнения** (`exercises`) — библиотека отдельных упражнений: название, группа мышц, инвентарь, инструкция, картинка. Источник данных — [Free Exercise DB](https://github.com/yuhonas/free-exercise-db) (public domain, импортируется в Firestore один раз скриптом, без внешней API-зависимости и лимитов)
2. **Программы** (`programs`) — готовые многонедельные программы тренировок, собранные из упражнений. Курирует только админ (ты)
3. **Тренировки** (`workouts`) — личные тренировки пользователя: либо взятая готовая программа, либо своя сборка из библиотеки упражнений. У каждой тренировки — **полный лог выполнения** (дата, вес, повторы) для истории и статистики прогресса в личном кабинете

## Роли и доступ

- **Регистрация открытая** — email/пароль или Google, без белого списка/инвайтов
- **Админ (ты)** управляет каталогом упражнений и программ через **отдельный admin-экран в приложении** (не через консоль Firebase)
- Обычные пользователи: просматривают каталог, собирают свои тренировки, ведут лог выполнения, видят свой прогресс
- **Статус админа** хранится в документе `settings/admins` (массив uid), а не в custom claims — их без Cloud Functions выставить нельзя. Список правится только вручную через консоль Firestore или Admin SDK: из клиента запись закрыта (`allow write: if false`), потому что сайт публичный. UID для добавления виден в «Профиле»

## Порядок реализации

1. Миграция на Firebase — подключить Auth (email/пароль + Google) и Firestore, снести `server/`
2. Импорт библиотеки упражнений из Free Exercise DB в Firestore (разовый скрипт в `scripts/`)
3. Admin-экран — добавление/редактирование упражнений и программ
4. Пользовательские тренировки — сборка своей тренировки из библиотеки упражнений
5. Лог выполнения — отметка факта тренировки (вес/повторы/дата) + история
6. Личный кабинет со статистикой — графики прогресса на основе лога
7. Деплой — Firebase Hosting + Firestore rules (Spark-план, без Cloud Functions)
